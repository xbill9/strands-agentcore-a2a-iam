# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout and running

- Two halves: `strandsiam/` is an AgentCore CLI project (the deployed Strands A2A worker, `app/agent/main.py`, with its own `pyproject.toml`); the repo root holds the local side (`caller/`, `bench/`, `iam/`) with no manifest — deps are `pip install 'strands-agents[a2a]' 'bedrock-agentcore[a2a]' boto3 httpx` into the active `python3` (3.11+, `bench/common.py` uses `dt.UTC`).
- Run `caller` and `bench` as modules **from the repo root**: `python3 -m caller.ask "..."`, `python3 -m bench.latency --runs 10`.
- `agentcore` commands run from `strandsiam/`. Region is **us-east-1**: `agentcore deploy --yes --region us-east-1` (CLI 1.0.2 has no `-y`; run `npm ci` in `strandsiam/agentcore/cdk` once per clone). `deploy` doesn't print the ARN; `agentcore status --region us-east-1` does.
- `strandsiam/agentcore/cdk/` is generated by the AgentCore CLI; change `agentcore/agentcore.json`, not the CDK code.
- Everything needs `WORKER_RUNTIME_ARN`. Region and account are parsed from it; there is no separate region setting. `iam/setup_roles.sh` creates the three `speedrun-caller-*` roles from it.
- The AWS login is the root user, which AWS refuses to let assume roles. Benches run as `AWS_PROFILE=speedrun-operator` (IAM user allowed only `sts:AssumeRole` on `speedrun-caller-*`); run `setup_roles.sh` as root with `CALLER_PRINCIPAL=arn:aws:iam::<acct>:user/speedrun-operator`.

## SigV4 / AgentCore gotchas

- Every request, including the agent-card GET, is SigV4-signed for service `bedrock-agentcore` (`caller/sigv4.py`). Only `host`, `content-type` and the session header are signed — don't add signed headers httpx may rewrite.
- Runtime URL: `https://bedrock-agentcore.{region}.amazonaws.com/runtimes/{quote(arn, safe='')}/invocations/` — whole ARN percent-encoded, trailing slash required.
- `X-Amzn-Bedrock-AgentCore-Runtime-Session-Id` must be ≥33 chars (UUID4). New ID = cold session, reused ID = warm.
- `BEDROCK_MODEL_ID` must be an inference-profile ID (`us.` / `global.` prefix); default `us.amazon.nova-micro-v1:0`.
- The worker's model does no arithmetic: the `convert_currency` tool computes with `Decimal` and the prompt makes the model copy its JSON. Keep it that way.
- One request at a time per runtime session: a concurrent second request gets `409 Conflict`. Strands runs a turn's tool calls concurrently, so `caller/coordinator.py` serialises worker calls with a lock.
- `InvokeAgentRuntime` and `GetAgentCard` are both checked against `<runtime ARN>/runtime-endpoint/DEFAULT` as well as the bare ARN; `iam/invoke-policy.json` grants both on both. The runtime-only role omits the endpoint on purpose (the boundary bench shows the refusal).
- Benches assume the speedrun roles with retries because IAM changes take seconds to propagate; don't remove the retry loop.

## Results and the article

- Benches write `results/<UTC stamp>/*.json` with the account ID replaced by `ACCOUNT_ID`; these files are committed. Never commit a file containing a real 12-digit account ID.
- This repo is the CB Speed Run 2 entry (see `SPEEDRUN.md`). Every figure in the article comes from `results/` files.
- Root `.gitignore` ignores `strandsiam/agentcore/.cli/`, so the un-ignore of `.cli/deployed-state.json` in `strandsiam/.gitignore` has no effect.
- `strandsiam/app/agent/README.md`'s Memory section is template leftover; there is no memory resource.
